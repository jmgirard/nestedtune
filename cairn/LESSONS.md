# Lessons

_Durable "how this repo behaves" notes — build quirks, testing tricks,
toolchain gotchas. Captured at milestone end, harvested at plan time._

_One lesson per line. Current knowledge, not history: a lesson proven false
is **corrected in place** and marked (`(M07, corrected M11)`); git holds the
original. A lesson is **retired** — leaving no line behind — once a test
fails on the mistake it warns about, another tracking file's slot owns the
content, or a matured family graduates whole into a doctrine module._

_Hard cap: 50 lines._

## Lessons

- 2026-07-26 (M03): tune's failure surfaces are not where you would look. `tune_grid()` returns *normally* (with a warning) when every candidate fails — `select_best()` and `collect_metrics()` are what raise — and `last_fit()` never raises at all, handing back a result whose `collect_metrics()` is `NULL`. Catching only thrown errors records a failed fold as a success carrying nothing. The tunable set surprises the same way: `tune::extract_parameter_set_dials()` omits a parameter the engine cannot tune (`penalty` on the `lm` engine) even though it is marked with `tune()`, so a grid that omits it passes a tunable-set check and `tune_grid()` raises later — useful as a test vehicle, a trap for any check treating the set as complete.
- 2026-07-26 (M04, consolidated M12): cli output, twice over. Reading it: cli writes to `stderr()` whenever a sink is active on stdout, so `capture.output()` around a cli-based print method captures nothing at all and every assertion on the result passes or fails for the wrong reason — capture with `cli::cli_fmt()`, or let `expect_snapshot()` handle it. Writing it: `cli_alert_*()` emits one unwrapped line however long the string is, while `cli_bullets(c(i = "..."))` wraps at console width with a hanging indent, so any user-facing sentence longer than a clause belongs in the latter. Extended M24, two pluralisation traps a snapshot will not catch for you: cli takes every plural's quantity from the LAST interpolation, so `{n_bad} of {n_total} daemon{?s} {?is/are}` agrees the verb with `n_total` — insert `{cli::qty(n_bad)}` before it, which sets the quantity without printing. And `cli_vec()` uses THREE separator styles, `vec-sep` between all but the last pair, `vec-last` for the final pair at n > 2, and `vec-sep2` for the only pair at exactly n = 2; setting `vec-last` alone renders two items with no separator at all. Both were invisible to a snapshot that happened to pin n = 1 and n = 5 — pin the counts at which the wording changes, not the ones that came out right.
- 2026-07-26 (M05): an oracle asserting only the selection and the predictions does not guard where a seed is set, because a different RNG state usually picks the same candidate anyway and the fit is seeded separately. Assert the resamples the tuning run actually saw — and prove any such guard by inversion, since the plausible-sounding one here passed the mutation.
- 2026-07-26 (M05): a design's stored `inside` call travels without its environment, so any helper that parameterizes its resampling (`nested_resamples(..., inside = vfold_cv(v = v))`) produces a design that cannot be re-evaluated later. The repo's own `det_nested()` did exactly this; fixtures for anything that re-runs a specification need literal arguments.
- 2026-07-26 (M05, trimmed M18): inlining a data frame into a call with `rlang::call_modify(cl, data = df)` makes every downstream condition deparse the whole frame into its message — 1,194 characters on a 30x2 frame, growing with the data. Bind it to a name in a child environment and pass the symbol instead wherever the call may error. `nested_resamples()`'s two sites are now enforced by a test asserting the message is size-invariant and under 500 characters; `eval_inside_spec()` on the final-fit path is **not** — verified at M18 by mutation, reintroducing inlining there leaves the suite green.
- 2026-07-26 (M05): `tune::fit_best()` needs `save_workflow = TRUE` in the tuning run's `control_grid()`, and given that it reproduces a hand `finalize_workflow()` + `fit()` exactly under the same seed — a free third oracle strand written by neither the package nor the test author.
- 2026-07-26 (M06): `nested_results$.selected` is a list column of one-row tibbles, so `res$.selected$mtry` is `NULL` rather than an error — stack it with `do.call(rbind, ...)` before reading a parameter out. A vignette counting distinct values rendered "0 distinct values" and built perfectly cleanly.
- 2026-07-26 (M06): a vignette using a Suggests package needs `requireNamespace()` + `knitr::knit_exit()` to survive CRAN's noSuggests flavor. Chunk-level `eval = FALSE` is not enough, because inline `r` expressions still evaluate and error on the objects the skipped chunks never created.
- 2026-07-26 (M07): mirai starts every daemon on its own L'Ecuyer-CMRG stream, so a caller who has selected that same kind gets serial/parallel identity even from an implementation with no RNG kind pin at all. A test meant to catch a missing pin must use a third kind (Wichmann-Hill works); L'Ecuyer-CMRG is the one non-default kind with zero detection power. And mirai's two failure shapes both defeat the obvious check — neither `miraiError` nor the bare `errorValue` from a dead daemon inherits `"condition"`, and `conditionMessage()` *raises* on the latter. Classify what a worker returns by positively validating the expected shape, never by asking whether it is an error.
- 2026-07-26 (M08, consolidated M14): two faceting traps. A ggplot2 `breaks` function is shared across panels but called once per panel with only that panel's limits, so any per-panel decision must be recoverable from the limits alone — deciding it over the pooled column silently changes every *other* panel, which is how a fixed break defect came back for any grid mixing an integer parameter with a continuous one. And `facet_wrap()` defaults to `drop = TRUE`, so a factor level with no rows loses its panel entirely, while a faceting variable with no values at all builds fine and errors at *draw* time from inside ggplot2; `drop = FALSE` fixes both, and `scale_x_discrete(drop = FALSE)` is the same guarantee for an axis.
- 2026-07-26 (M08): assertions on `ggplot_build()` cannot see the part a reader meets. Rendering the figure and looking at it found a subtitle clipped at 7 inches and fractional breaks labelling three unanimous integer choices 2.950/2.975/3.000 — both invisible to a green 51-assertion suite. Render every new plot before approving its snapshot.
- 2026-07-26 (M07, extended M14): a test that hand-rolls the code path it means to cover pins nothing. `dispatch_folds()` looks its worker up by name and serializes it, so `local_mocked_bindings()` does reach a mirai daemon — check that before concluding a path is untestable. The same trap at harness scale: `test_local()` (pkgload, one file per process) and `test_check()` (installed package, every file in one process) are different daemon paths — `prime_daemons()` does real work under the first and is a no-op under the second — so a reproduction harness built on the wrong one stresses a configuration the failure never occurs in.
- 2026-07-26 (M09): `conditionMessage()` dispatches to a method **mirai** registers, so a test that fabricates a `miraiError` works only where mirai is loaded — and it gets loaded by `skip_if_not_installed()` in an *earlier* test, so the file passes locally and errors under noSuggests. Fabricate an object belonging to a Suggests package only in a test that also gates on that package.
- 2026-07-26 (M09, corrected M14, extended M19/M38): assertions that cannot fail — six, and the pattern is one to check for by hand. `system.time()` measures only after a call returns, so it flags a slow run but never bounds a hang; `setTimeLimit(elapsed =, transient = TRUE)` bounds one only where R reaches its evaluator, and M14 established by execution that it does **not** interrupt a blocked `mirai::collect_mirai()` — a wedge there is unrescuable from R and only an outside kill ends it. `tryCatch(expr, condition = identity)` catches *warnings*, so a variable assigned inside it stays `NULL` whenever the code merely warns, making `expect_null()` on it vacuous. `identical(.Random.seed, before)` cannot show a check fired *before* the RNG was drawn from, since both drivers install their restoring `on.exit()` before drawing — `exists(".Random.seed")` in a never-drawn session is what discriminates. A PASSING test is not evidence until you check it runs the claim's code path (M21: `order()` on a list column was pronounced safe on a green test that only ever ordered a character vector; the real call site raised, and the false conclusion reached a shipped comment). `tune::collect_metrics()` on a `tune_results` returns `mean`/`n`/`std_err` and **no** `.estimate` unless `summarize = FALSE`, so a loop over `$.estimate` iterates `NULL` (M22). And comparing two values one function produced from one deterministic input agrees by construction. M26 adds two more: a top-level `on.exit()` in an `Rscript` registers against a frame that never returns and silently never fires — `reg.finalizer(environment(), ..., onexit = TRUE)` is the script-level equivalent — and `!identical(int, dbl)` is TRUE on type alone while `sum(parts) > whole` holds structurally for any multi-member serialization. M38 adds the mutation check that mutates half the code: under `pkgload::load_all()` every internal function is bound in TWO environments — the namespace, where the package's own functions resolve it, and the attached `package:` env, where a test helper defined in the global env resolves it — so patching only the namespace leaves the tests' own copy intact. Restoring `id_columns()`'s name pattern in the namespace alone redded 30 of a 108-cell sweep and made its atomic axis look blind; patching both redded 60, 30 atomic and 30 list. Edit the source and reload, or check with `identical(body(get("f", envir = environment(helper))), body(patched))` before believing a low red count.
- 2026-07-27 (M10): `mirai::everywhere()` is how you reach every daemon — one result element per connection, and it queues behind a busy daemon rather than skipping it — but it takes no `.timeout`, and collecting a `mirai_map` with `[` BLOCKS until every element resolves. Bound it by polling `unresolved()` to a deadline, then `stop_mirai()`, then reading each element's `$data`, which yields `unresolvedValue` instead of waiting. Extended M24: it captures its expression unevaluated and serializes it, so the daemons evaluate whatever the HOST's copy of that function body has been rewritten into — under `covr` that is a `covr:::count()` call inside every `{` block, and a daemon whose library has no covr raises on it, returning a `miraiError` that a positive validator rightly refuses, so a pool that answered perfectly is classified as silent. It failed only the coverage job and passed all five `R CMD check` legs. Build the sent expression with `str2lang()` from a string: a string is data, not source, so no rewriting tool reaches it.
- 2026-07-27 (M11): `git diff-tree -m --first-parent` is not a first-parent diff — `--first-parent` is a traversal option `diff-tree` ignores, so `-m` emits one diff per parent and `--no-commit-id` concatenates them into a union. Use `--diff-merges=first-parent`, and `--root` beside it or a root commit (this repo has one) reports no files at all.
- 2026-07-27 (M12, extended M20/M23): `rlang::hash()` is not stable across two identical constructions of a tidymodels object — a recipe's `terms` quosures capture the frame that built the recipe, and `metric_set()`'s closure environment refers to itself; serialization resolves those cycles by reference and the numbering does not survive re-construction. Hash a canonical form instead: environments expanded by contents, named environments taken by name, cycles cut. Corollary: that form expands a closure's lexical environment, so hashing a *function* re-keys whenever anything mutable in its scope changes, while package functions are safe because a namespace is taken by name. The fixture cache keys on the call, its canonicalized arguments and the RNG state — and on nothing about daemon state, so a `memoised()` run written in the house style inside a daemon-backed test is served the serially-built value, dispatches nothing, and passes under the very defect the test exists to catch: build parallel fixtures inline and assert `last_dispatch()`. A cache hit also returns an object whose `metric_set()` is a different closure, so `expect_identical()` against a locally bound set fails on correct code. The same mechanism governs the wire (M23): R serializes an ordinary environment by CONTENTS and `globalenv()`/namespaces BY REFERENCE, so a formula written at a user's top level weighs nothing while the identical formula written inside a function drags that function's whole frame — 26,549,958 B against 1,761 B, in a harness whose own workflow was the leak.
- 2026-07-27 (M15, extended M16): stopping mirai work, and testing that you did. A real console interrupt *does* unwind a blocked `collect_mirai()` and R runs `on.exit()` on the way out — the one bound that reaches it where `setTimeLimit()` does not — but `stop_mirai()` only cancels on a dispatcher-backed pool: with `daemons(n, dispatcher = FALSE)` (indistinguishable through `status()$connections`, and `status()$mirai` is `NULL`) it returns `FALSE` per element and the tasks run to completion, while on a resolved map it is inert either way, which is what makes an unconditional cancelling `on.exit()` safe. Testing it needs a genuine SIGINT: have the workers write marker files and a detached `sh` wait for them before `kill -INT $PID`, and make the kill conditional on those markers — fired unconditionally after a timeout it lands in whatever test is running twenty seconds later and aborts the run. Two teardown facts M16 measured: `daemons(0)` returns in ~0.2 s with a live task outstanding — it does not block, it orphans the task — and `daemons(url =)` on an occupied port raises `10 | Address in use` in ~0.03 s, so neither can wedge a suite.
- 2026-07-27 (M14, corrected M16, extended M23): a test suite says nothing about itself unless you make it. Under `R CMD check` the suite's output reaches the job log only as an end-of-run dump, so every line arrives stamped alike and an in-band clock is the only timing there is; testthat's check reporter buffers, while `stderr()` is unbuffered and survives a killed process. Reporting through it needs a `Reporter` subclass — R6 members are locked, so a stock instance cannot be patched — and `check_reporter()` returns the string `"Check"`, not the object `MultiReporter` wants; a class defined in `tests/testthat.R` is invisible to every test file, because testthat sources helpers and never the runner. A bare `Rscript` sets no `NOT_CRAN`, so every `skip_on_cran()` test skips and a harness finishes clean having asserted nothing: assert the assertion count. A RED run under-reports too — testthat's default reporter stops after 10 failures, so a mutation check read off it named five of the seven guards that fired and looked like a narrow result rather than a truncated one (`SummaryReporter$new(max_reports = Inf)` shows the rest). Corrected M16: testthat DOES expose per-test hooks, `Reporter$start_test(context, test)` and `end_test()`, firing once per block with its description.
- 2026-07-27 (M17): pkgdown publishes repo-internal markdown. `pkgdown:::package_mds()` globs every root and `.github/` `.md` against a hardcoded exclusion list with no config knob, so `CLAUDE.md` became `CLAUDE.html` on a public site. Deleting the built HTML afterwards is not enough: `get_site_paths()` globs every `docs/**/*.html` and both `sitemap.xml` and `search.json` derive from it, so the page stays listed and its full text stays searchable. Remove the source before the build. `.Rbuildignore` does not help — pkgdown builds from the source tree, not the tarball.
- 2026-07-27 (M17): naming a package in a workflow's `extra-packages: any::<pkg>` beside `needs: <slot>` makes the matching `Config/Needs/<slot>` field in DESCRIPTION decorative — the action installs it either way, so nothing ever fails if the field is wrong or absent, and a criterion asserting the declaration works cannot fail either. Name only `local::.` and let the slot resolve the rest. Relatedly, a job-level `permissions:` block replaces the workflow-level one outright, so a workflow-level default is dead code in a single-job workflow.
- 2026-07-27 (M16): every wait being individually bounded does not bound the suite. `test-parallel-classify.R` typically ran 12.0 s while its declared bounds permitted 1008.7 s, and a CI cap killed it at ~17 minutes looking exactly like a hang. Sum the declared bounds per file and hold the total under the cap; and a bound copied from a call site into a ledger needs a test that re-reads the call site, or the two drift in silence. Extended M21: that re-reading is anchored by `file:line`, so inserting anything above a budgeted call — one fixture line and one test — made all 30 rows stale at once and failed three guards; adding no wait still costs a renumbering pass. Extended M31, on the caps themselves: two CI caps that look interchangeable are not. GitHub deletes an Actions cache untouched for 7 days, and a job-level `timeout-minutes` that kills a cold from-source dependency build kills it *before* the cache-save step, so the cache that would make the next run fast can never be written and every run pays the cold build again — a deadlock a job cap alone cannot leave. Split the scopes: the job cap sized for the slowest legitimate install, the hang bound on the step the hangs are in. `timeout-minutes` on a `uses:` step IS honored for a composite action (actions/runner#599, merged 2020); the open runner issues (#1979, #2415) are about `timeout-minutes` on steps written *inside* a composite definition, which is a different thing. And a figure justifying a job-scope cap does not carry over when the cap moves to a step: "1 of 394 jobs passed 20 minutes" says nothing about how long any check step ran.
- 2026-07-27 (M13, extended M23/M26/M27): measuring object size, four ways it misleads. `lobstr::obj_size()` charges content shared between objects once, so it is not additive — a per-object storage model over-predicts a whole-structure measurement, and a model landing under one is not thereby conservative; check which way each term errs before claiming a direction proves anything. Serialization is the mirror image: `serialize()` does NOT preserve that sharing, so one fold's payload holding six references to one frame measured 946.94 kB in memory and wrote six literal copies. An in-memory assertion is therefore structurally blind to anything crossing a process boundary — measure the serialized stream, and count copies with `grepRaw()` on a NUMERIC column's bytes, never a character one, since R memoises CHARSXPs through the string cache and a character column reports one copy where there are six. A serialized stream is also not byte-stable ACROSS PROCESSES — the pid's hex string rides inside it via temp paths and region names — so cross-process comparisons need a stated band, never equality; within-process reruns are byte-identical, and dev-state figures are a separate trap (`load_all()` against an installed package with srcrefs stripped moved one worker closure from 291,491 B to 524 B). Finally the byte search itself can read a coincidence: a subset frame that happens to keep the sentinel's source rows contiguous reproduces its bytes without being a copy, so net out each candidate frame's own contribution before reporting a count. Figures and derivations: `references/mori-backend-assessment.md`.
- 2026-07-30 (M18): `set.seed(s)` pins only the uniform generator, so a fixture whose *property* was found by search — not merely its values — is not reproducible under a different ambient `RNGkind()`. The metric-separation fixture split 3 of 3 outer folds by default, 1 of 3 under `normal.kind = "Box-Muller"`, and 0 of 3 under `L'Ecuyer-CMRG` or `sample.kind = "Rounding"`, while its comment claimed reproducibility. Pin the full triple the way the reference loops do, and restore the caller's kinds so the pin does not leak into the next file.
- 2026-07-30 (M19): `length(workflow$pre$actions)` is not "has a preprocessor" — `workflows::add_case_weights()` files an action under `pre` too, so a workflow with a model and case weights but no formula, recipe or variables counts as one, slips a guard written that way, and still fails every fold. Ask `names(pre$actions)` for `formula`/`recipe`/`variables` by name. The same count also described that workflow as carrying "a preprocessor only".
- 2026-08-30 (M30, extended M31): a red macOS `R CMD check` leg can fail entirely upstream of this package. `gower`'s RSPM macOS binary references the OpenMP symbol `___kmpc_barrier` with no libomp on the runner, so `dlopen` fails, `nestedtune` never installs and the leg dies in ~1m36s — twice, identically, so not a flake. The maintainer's Mac is the same `aarch64-apple-darwin` and R version as that runner and its `gower.so` links only libR and libSystem, so a local `devtools::check()` passes and is the evidence that separates an upstream break from ours: read `otool -L` on the offending `.so` before assuming the diff caused it. The narrow remedy is pak's per-package `?source` parameter — `extra-packages: any::rcmdcheck, gower?source` — which rebuilds that one package and leaves every other package, and every other matrix leg, on the binary path; scope it with a `matrix.config.os` ternary rather than putting a whole job on source builds.
- 2026-08-30 (M28): a claim about another package's export surface is not checkable from recall, and four review passes each found a new counterexample. Assuming a helper unexported was wrong for nine of them at tune 2.1.0; the fix — re-reading every symbol the page *cited* — then missed `new_bare_tibble()`, which was never cited because nobody looked; a stated sweep reading all 152 tune and 62 rsample `export()` names against every entry still missed `.catch_and_log()`, the exported wrapper onto four unexported helpers, and a fourth `@keywords internal` doc topic. Name-matching would have caught none of the four the sweep did find — no upstream name shared a substring with the local function it duplicates. Two things follow: sweep the whole `NAMESPACE` by reading what each name does, never by matching names or checking the ones you already cited; and an *exported* symbol under `#' @keywords internal` is not a counterpart you may lean on — the fact that matters is the absent stability promise, not absent visibility, which changes the ask from "export this" to "promise this". Extended M35: the same holds for another package's *argument defaults*, and two consecutive reviews got one wrong in opposite directions from recall — `tune::control_last_fit()` defaults `allow_par = FALSE` at tune 2.1.0, which one review read as `TRUE` and the code comment answering it then described as parallelism left enabled. Read `args()` before writing a sentence about a default, and where a convention depends on one, state it in the call rather than inheriting it. Extended by the #37 hotfix to a third kind of claim, another package's *conditional* behaviour: `tune::attach_pkgs()` attaches a workflow's `required_pkgs()` only when the strategy is not sequential, so a `tune_grid()` running sequentially inside a mirai daemon attaches nothing and an unqualified recipe selector (`all_numeric_predictors()`, a quosure resolved through the search path) fails on every fold while the identical serial call succeeds off the caller's own attached packages. D-030 had asserted the opposite from recall — that `pkgs` was "already guaranteed on the parallel path by the daemon pre-flight" — and the pre-flight only ever probed nestedtune itself. Where a fix depends on what an upstream function does *under a condition*, read that branch of its body, and where the condition is one this package forces, assume nothing carries over from the branch it never takes.
- 2026-08-30 (M33): a repository-wide reformat invalidates every `file:line` citation the repo's own records hold, not just the ledger the milestone knows about. `air format .` over 60 files moved 124 citations across `references/` pages, `ROADMAP.md`, `benchmarks/` notes and one source comment, while the milestone re-pointed only `helper-time-budget.R`'s 71-row budget ledger, which is the one a test enforces. Nothing catches the rest: the ledger's cross-check re-reads its own file/line/call columns and never free prose, so even the helper's own header comment (`classify:693 sets it, :699 spends it`) went stale inside the file that was re-pointed by hand. The repair is a `difflib` line map over each touched file's before/after text, applied only where the cited position's content actually moved — but it must not run blind: this repo's pages cite `tune`'s `R/checks.R` and `R/parallel.R` by the same relative paths its own files use, so three sites had to be restored by hand. Verify by resolving each citation back to the symbol it names, not by re-running the mapper. Extended M34: `format-suggest` runs at `fail_level: error`, so one hand-written line past air's width reds the PR in 12s — run `air format .` on anything you hand-edit before pushing, and take the reviewdog suggestion verbatim rather than reflowing by eye. Extended M37: the same "verify the hand-edit landed where you meant" applies to `DECISIONS.md`, whose commented template block sits at the *end* of the file, so a D-entry appended by finding the end of the file lands inside it and renders nowhere — `b26eb77` fixed exactly that for D-030 and D-035 repeated it one commit later. Append above the `<!-- Template:` line and re-read the heading in rendered position before writing the record that cites it.
- 2026-08-31 (M35): a review lens pointed at the local default branch reviews the wrong diff. All three M35 lenses were given `main..HEAD` while local `main` sat 6 commits behind `origin/main`, so 35 files reached them instead of 23 and three of the fourteen findings were about an external PR already merged — real defects, but nobody's to fix at that gate. Spawn lenses against `origin/<default>..HEAD`, and `git fetch` before comparing: the sync step at the top of review updates the branch, not the local default-branch ref that the lens prompts then name.
- 2026-08-31 (M36): a rule that must tell a class's OWN columns from a caller's cannot derive them from a name pattern, because the two namespaces overlap and every narrowing buys only the next name. `nested_results` found the design's fold-label columns by grepping `^id`, so `ideal` and `id_extra` counted as the design's: an added one could not be removed again, and an added list column became an `order()` key that aborted with `unimplemented type 'list' in 'listgreater'` from inside the rule. Narrowing to `^id[0-9]*$` — exactly what rsample names them — moved the same three defects onto `id2`, `id0` and `id9`, which a caller may equally add, and shipped a NEWS sentence promising an added column is left out "whatever it is called". Three review rounds each fixed the previous name. Trimmed M38, which shipped the record and the tests that enforce it: the prescription this line carried (record what the constructor wrote; narrow the user-facing claim to what the code does) is now red-on-mistake — restoring the pattern derivation reds 60 of the 108-cell method sweep, and a doc block reds on the narrowing sentence coming back. What is left is the diagnosis, which no test can carry: the overlap is between the two namespaces, so no spelling separates them and only the party that named the columns knows which is which.
- 2026-09-01 (M41): adding a grouping key to a shared summarizer changes the shape every reader of it consumes, not just the two the change was made for. `summarize_folds()` gained `.eval_time` for `collect_metrics()` and `summary()`, and `autoplot(type = "performance")`, which reads the same function to name its panels, aborted on a duplicated factor level that no test reached until review round 2. Before declaring a shape change done, grep every caller of the summarizer and run each on the new shape.
- 2026-09-01 (M42): a guard's message is tested with the argument shape its real callers use, not the shape the test file writes. `fixture_key()`'s depth guard read `names(args)` to name the deep argument, and every test request named its arguments, so the message named one in the tests and nothing ("argument(s) `` nest past") on the positional calls `memoised()` and every real fixture make; review round 1 returned the milestone on it. Build one request the way the production caller builds it — here `as.list(call)[-1L]` with positional slots — and assert the message on that.
- 2026-09-01 (M43): testthat hands an `expect_snapshot()` `transform` each cli message on its own, not the block as recorded, so a transform that looks past its message for context (the next bullet, the next section) sees nothing there. `scrub_tibble_body()`'s first cut searched for the bullet after the tibble body and errored on the lone message; the transform must be right about a vector holding only the lines it is scrubbing.
- 2026-09-01 (M44): a table that adds its own columns beside user-named ones overwrites a same-named column silently — `out$n <- count` over `agreement()`'s key list turned a parameter with id `n` into the count, indistinguishable from an untuned run — so any result keyed on user-chosen ids refuses or namespaces the collision, and a test plants it.
