- Variance estimation / inference on the nested estimate — added 2026-07-25 — G6; needs oracle-grade literature support before it is plannable. Literature reached the shelf 2026-07-31: `references/bates2023.md` shows CV intervals under-cover because fold errors are correlated _(corrected 2026-07-31: this row read "proves the naive CV standard error is too small … which is the same formula `R/nested-results.R:213-217` computes"; `references/bates2023.md`'s own Open Questions record that his statistic is a CV over points and ours an SE over V fold means, and that the two are **not** the same statistic — unmeasured here, so the sameness was never established; git holds the original)_, and `references/krstajic2014.md` argues no single nested run is usable for assessment (its pitfall 4). So the caveat half is now writable and the interval half still is not. **Restated 2026-07-31** on ingesting the inference sources: "no method exists" is no longer the blocker. `references/bengio2004.md` gives the negative result in its strongest form — no *universally* unbiased variance estimator, and §5 adds that repeating the outer splits does not help, since extra runs are not independent realizations, which kills the workaround Krstajic's min–max range invites. `references/bayle2020.md` gives an asymptotically exact CI for k-fold test error, O(n) to compute from per-point losses, with a reference implementation at `alexandre-bayle/cvci` — two GP2 oracle types from one source if this is ever planned. `references/austern2020.md` shows the V-fold variance reduction is V·(1+2ρ/(σ₁²+σ₂²))⁻¹ with ρ's sign a joint property of algorithm *and* data distribution (1.638 vs 2.367 for the same estimator at V = 2), so no fixed divisor is right for all users. Three specific blockers remain, and a plan would have to clear all three: (1) loss stability γ_loss = o(σ²/n) is unestablished for a tune-then-fit procedure, and `references/cawley2010.md` measures how much selection swings with the sample while bayle2020 §5.3 shows instability inflates test size; (2) the valid interval's estimand is the k-fold test error of the rules this run fitted, not the error of the final model; (3) the estimators need per-observation losses, and `R/nested-tune-grid.R:385-396` keeps only `collect_metrics(fitted)` per outer fold, discarding the `last_fit()` result and its `.predictions` — so retention cost must be priced against M23's lean payload before anything else. **Restated again 2026-07-31** on ingesting the tier-1/2 sources: a fourth blocker appears and it is categorical, not practical. `references/luo2026.md` (Bernoulli 32(3)) bounds the power of *any* assumption-free valid black-box test of a procedure's risk by α·(1 + (τ̃−R)/(R_max−τ̃))^{N/n}; v-fold nesting runs at N/n = v/(v−1) ≈ 1.11 at v = 10, so an assumption-free interval for this estimand cannot exist at the ratio the design uses — "nobody has built it" was the wrong reading. Blocker (1) also splits: `references/nachum2026.md` adds squared loss stability (weaker than loss stability, necessary under low loss variance) and shows loss stability is not necessary in general; `references/luo2025.md` shows the closest studied stability notion is uncertifiable from data without exhaustive search; `references/bayle2026.md` shows bayle2020's condition is the *ratio* r = nγ/σ² and that it fails for comparisons of two individually stable algorithms — so nothing here may ever test "workflow A beats workflow B". - An analytic oracle for the outer loop via `parsnip::null_model()` — added 2026-07-31 — from `references/nachum2026.md`. Theorem 4.10 plus Lemma 4.9 give an exact closed form for the k-fold CV MSE of the majority algorithm under Bernoulli(1/2) labels: MSE = ((k-1)/k)*Cov(n,m) + 1/(4n) with Cov(n,m) = 2^-n * sum_j C(m-1,j)^2 * C(n-2m, floor((n-m)/2) - j). `parsnip::null_model(mode = "classification")` instantiates that algorithm and carries no tuning parameters (verified present 2026-07-31). Would be the shelf's first GP2 type (3) oracle for the outer loop. Two unmeasured risks before it is plannable: `null_model()`'s tie-breaking at Y = n/2 is unchecked against the theorem's `Y > n/2` rule, and MSE is a distributional property, so the replicate count must be priced against GP4 the way `references/varma2006.md`'s null-data invariant already was
