# M35: The factor level a caller can name as the event

**Status:** done (2026-08-31, PR #43 https://github.com/tidymodels/nestedtune/pull/43)

**Goal:** Let a caller name which factor level counts as the event, on both orchestrators and on both loops, instead of every classification metric being computed against the first level.

**Outcome:** `nested_tune_grid()` and `nested_final_fit()` take `event_level` after `...`, defaulting to `"first"`, validated by `check_event_level()` (`R/checks.R`) before either orchestrator's seed draw. It reaches the inner `tune::control_grid()` on both — threaded through `dispatch_folds()`, both dispatch shapes, `fold_task()`, `nested_fold_fit()` — and on `nested_tune_grid()` a `tune::control_last_fit(event_level, allow_par = FALSE)` on the outer scoring fit, which had taken no control object since M02, so outer-fold `sens`/`spec` were computed at the first level whatever the inner run had been told. Roxygen's "Differences from calling tune directly" became three lists — settable, forced, not offered — naming why each `control_grid()` slot is withheld. Test surface: the two-class `cls_*` fixture (`helper-orchestration.R`; n = 120, 32 events, stratified, `metric_set(roc_auc, sens, spec)`), `test-event-level.R` on three oracles (a tune-free refit count, an independently-run `tune_grid()`, the sens/spec level exchange), and `BC7` in `test-parallel-identity.R`. Discovered repairs to pre-existing breakage: the drift check's substring match (T0, now guarded on both sides), `test-ci-workflows.R` against main's single-job pkgdown rewrite (T10), `README.Rmd`'s `.Rbuildignore` entry (T11).

**Decisions:** D-030 — `event_level` as its own argument rather than a `control` argument taking tune's settings object.

**Review:** Three passes; two defect returns (AC6 red on a stale branch after main moved, then the consistency gate on weight caps). The third verified all six criteria and passed the gate: suite 1738 pass / 0 fail, `check()` 0/0/0. Full three-lens fan-out — [S] blame no finding, [S] prior-review 4, [O] diff-bug 10. Nine fixed at the gate: the `allow_par` comment that misstated tune's default (and `allow_par = FALSE` now pinned rather than inherited), the one-sided drift regex, a missing seed assertion on `nested_final_fit()`, a duplicated test label, two imprecise roxygen claims, an unused argument, the missing D-entry, a stale signature comment. Four to candidate rows: the fixture-signature enumeration, and three pkgdown-workflow regressions that arrived with external PR #30 rather than this diff. One rejected as intentional convention (internal hops defaulting `event_level`, as `param_info` does).
