# M54: The inner tuning call finalizes an unknown parameter range on the outer fold's analysis rows

**Status:** done (2026-09-03, PR #64 https://github.com/tidymodels/nestedtune/pull/64)

**Goal:** Every inner tuning call sees only its outer fold's analysis rows, so a parameter whose range tune finalizes from the data — by row count, by column count after preprocessing, or by the values — is finalized without the outer assessment rows, as IP1 requires and as a design from `rsample::nested_cv()` already gets.

**Outcome:** `analysis_framed_inner(inner, split)` (`R/nested-resamples.R`, beside `inner_resamples_from_split()`), called in `nested_fold_fit()` immediately before `run_tuner()` inside the fold seed's scope and drawing nothing: when the outer `in_id` has no repeats, every index is within the frame, and every inner split carries the outer split's own frame, each inner split is rebuilt with `$data <- rsample::analysis(split)`, `in_id`/`out_id` remapped through `match()`, and the rset fingerprint recomputed; a `nested_cv()` inner rset, a repeated-`in_id` outer split, or an out-of-range index leaves the rset untouched. Four of the five tuners finalize on that frame (`tune_bayes()` refuses an unknown range before any frame is read). Measured: on a 200-row frame with five outer folds, `min_n` candidates fell from up to 100 to within each fold's `[16, 80]`; a `nested_resamples()` design and the `rsample::nested_cv()` design with identical inner rows now return identical `.inner_metrics` and `.metrics`. Docs at the three `@param param_info` sites, the three `@section Reproducibility` recipes, `?nested_final_fit`'s `@param results` (the final fit still finalizes on the full data, its own training data), the DESIGN architecture paragraph naming the rebuild as the GP1 divergence, one NEWS entry. Tests: `test-nested-tune-finalize.R` (AC1 over the tuner registry plus an evaluated-`vfold_cv()` outer design, AC2 closed-form bounds, AC3 live `nested_cv()` reference, AC4 mocked `run_tuner()` on the two untouched designs) and the appended-index case in the failures file. Suite 4925 pass; `check()` 0 errors, 0 warnings, 0 notes.

**Decisions:** milestone-local: the analysis frame is materialized only after every inner index maps, so an outer split whose own `in_id` reaches past the data still fails at the outer fit, not the inner stage. Plan gate: rebuild the inner rset in the worker rather than pre-finalize `param_info` per fold, leaving tune's finalization, message and recipe refusal to tune (GP1); the /milestone-brief escalation on the ip-touching tripwire declined; the pre-1.0 deprecation cycle for the changed candidates waived, NEWS naming the change.
