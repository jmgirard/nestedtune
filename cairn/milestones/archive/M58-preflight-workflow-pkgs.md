# M58: The startup check asks every daemon for each package the workflow and the tuner need, and the host's entry check reads the same list

**Status:** done (2026-09-04, PR #68 https://github.com/tidymodels/nestedtune/pull/68)

**Goal:** A run whose daemons or host lack a package the workflow or the tuner needs is refused at entry, before any fold runs, naming the daemons and the packages.

**Outcome:** One helper, `needed_pkgs(object, tuner)` (`R/parallel.R`), builds the package list — `workflow_pkgs()`, which is `tune::required_pkgs()` of the workflow falling back to the engine's list when that call raises, plus the tuner registry's `requires` — and three readers share it: the daemon probe, `attach_daemon_pkgs()`, and the host's entry check. `daemon_probe_expr()` asks `requireNamespace()` for each of `pkgs` inside a `local()` ahead of its load branch, so a cannot-load daemon still answers the package question; `daemon_report()` requires the `missing_pkgs` field; `preflight_outcome()` counts daemons in `missing_pkgs`, unions names in `missing_packages`, and orders `cannot_load` > `missing_pkgs` > `incompatible` > `no_response` > `ok`; `check_daemons_can_load()` raises `nestedtune_daemons_missing_pkgs` under the shared `nestedtune_daemons_unusable` with the count, the packages, an install-then-restart remedy and the serial alternative, and its cannot-load branch carries a missing-package bullet (the incompatible branch does not, since the package rung outranks it). `check_model_spec()` (`R/checks.R`) is replaced by `check_workflow_pkgs()`, refusing under `nestedtune_pkg_not_installed` with a `deparse1()` install hint; `check_tuner_installed()` takes the same `deparse1()`.
