# M46: `nested_final_fit()` re-runs the procedure a result recorded

## Goal

A user hands `nested_final_fit()` the workflow and the `nested_results` whose
estimate they will report, and the model comes back from the same search that
estimate describes — grid or Bayesian — re-run over the full data.

## Scope

Surface tier: user-facing — an exported function's signature changes (D-041,
pre-1.0 under D-003) and the results object gains a recorded inner
specification.

**In:** `nested_final_fit(object, results, ...)`; the design's `inside` call
recorded on every `nested_results` by both orchestrators and carried through
`run_attributes()`; the procedure, the inner specification and the data read
from the results object, refusing one that lacks the record or has no rows;
the Bayesian final-fit path through M45's tuner description; oracles, RNG and
read-nothing-else tests; print, summary and `extract_scored_candidates()` for
a Bayesian final fit; docs and the vignette's final-fit section.

**Out:** `predict()`/`augment()` on `nested_final_fit` → existing ROADMAP
candidate row (added 2026-07-26). A final fit from a design alone, restating
the procedure → gone (D-041); `tune::fit_best()` and `tune::last_fit()` cover
that need. A results object built before this milestone → refused, not
migrated (pre-1.0).

## Acceptance criteria

- [x] AC1: `nested_final_fit(object, results, ...)` takes a `nested_results` in place of the design and procedure arguments; the inner specification comes from a new `inside` attribute both orchestrators record from `attr(resamples, "inside")` and `run_attributes()` carries, the data from the `splits` column, and the procedure from M45's `procedure` attribute together with `attr(results, "metrics")`. A `results` lacking `inside` or `procedure`, or with zero rows, is refused before any fitting with its own condition class naming the user's call; `object` is still checked by `check_workflow()`; the former `grid`, `param_info`, `metrics`, `event_level` and `eval_time` formals are gone and any of them is a `check_dots_empty()` error.
- [x] AC2 (live oracle; RB tripwire: no-oracle — the trade M45's work log records): for a grid result, the selected parameters, the tuning run's `in_id` splits and `predict()` on held-out rows are identical to the hand-rolled reference final fit `helper-orchestration.R` holds, fed the recorded procedure; for a Bayesian result, the same three are identical to a reference that sets the tuning seed with the kind pinned, evaluates the inner specification (D-016's order), calls `tune::tune_bayes()` with the recorded `iter`, `initial`, `objective` and `control_bayes(seed = <the tuning seed>, allow_par = FALSE)` — its initial set drawn inside that call from the same stream — selects, finalizes, sets the fit seed and fits on every row.
- [x] AC3 (invariant oracle): the final fits of a `nested_tune_bayes(iter = 0, initial = k, param_info = p)` result and of a `nested_tune_grid(grid = g, param_info = p)` result built on the same design, each run from the same entry seed, are identical in selection, in their tuning run's `in_id` splits and in `predict()` on the full data, `g` being `dials::grid_space_filling(p, size = k)` on the integer-only fixture, the test asserting that draw seed-independent as `test-nested-tune-bayes-oracles.R` does; and `tune::fit_best()` on the reference Bayesian run — `reference_bayes_final_fit()`'s `tune_bayes()` built with `save_workflow = TRUE`, which the AC2 strand in the same file asserts identical to the final fit's stored run on selection and `in_id` splits — run under the independently derived fit seed with the RNG kind pinned, reproduces the Bayesian final fit's predictions, the strand `test-nested-final-fit-oracles.R` records as O5.
- [x] AC4 (IP2): for a Bayesian result, the same seed gives an identical final fit and a different seed a different one, the worker's output does not depend on the ambient kind, the caller's RNG state and kind are restored on completion and on error, and a session with no `.Random.seed` is left with a valid one; and the final fit reads nothing from the fold rows but `splits` — a test overwrites every other fold-row column (`.metrics`, `.selected`, `.grid`, `.notes`, `.completed`, `.tuning_seed`, `.outer_fit_seed` and the label columns) by assignment on the unclassed columns, re-stamps the class and attributes rather than going through a verb, and gets the same selection, splits and predictions.
- [x] AC5: `print()` and `summary()` on a Bayesian `nested_final_fit` name the procedure with the initial count, the iterations actually completed read as the tuning run's largest `.iter`, and the requested `iter` shown separately as requested; `extract_scored_candidates()` returns the `.iter`-bearing candidate table M45's `scored_candidates()` derives.
- [x] AC6 (docs): the help pages of `nested_final_fit()`, its print and summary methods and both orchestrators' final-fit pointers, and the vignette's final-fit section, show the new signature; `NEWS.md` carries the entry; `cairn/DESIGN.md`'s final-fit family line and architecture paragraph are updated.
- [x] AC7: `Rscript -e 'devtools::document()'` produces no diff, `Rscript -e 'devtools::test()'` is clean, and `Rscript -e 'devtools::check()'` reports 0 errors and 0 warnings.

## Decisions

- 2026-09-02 (RR05 Q1): the Bayesian O5 strand runs `tune::fit_best()` on the test's reference `tune_bayes()` run built with `save_workflow = TRUE`, the shape RR02 Q5 fixed for the grid strand; the package's controls stay unchanged. Saving the workflow on the final-fit path was rejected: on a recipe workflow it stores a second copy of the training data beside the one the fitted workflow retains (RR05 P2/P3: +854 kB against 823 kB of data at 5000 x 20), opens `fit_best(extract_tune_results(x))` as a second final-model route on the ambient stream, makes the final-fit control diverge from the fold control, and adds no evidence beyond the selection and `in_id` identities the oracle file already asserts. Test-side attribute surgery (`attr(run, "workflow") <- wf`) rejected as resting on a private tune attribute. AC3's second clause is amended to this shape through the amendment gate (work log).
- 2026-09-02 (RR05 Q2): both tuners' final fits name their procedure in `print()`, one line, and carry the counts as summary components (`initial`, `iterations_completed`, `iterations_requested`; `NULL` on a grid fit, carried rather than omitted). The initial count and completed iterations are read from the scored candidates (`.iter == 0` rows; largest `.iter`), the requested `initial` and `iter` from the recorded procedure, both shown at every count. M40's hand-pinned print constant is re-agreed under a new name stating its new promise. Printed text points at "the results object this fit was built from"; roxygen links both orchestrators.
- 2026-09-02 (RR05 Q3): the results-record refusal is one class, `nestedtune_bad_results`, with a message per origin: not a `nested_results` (saying that a verb changing the rows returns a plain tibble); no `inside` or `procedure` record (naming both origins, an earlier version or a design carrying no `inside` call, and the remedy of re-running an orchestrator on this version, since a results object is not migrated); zero rows with the record present (a prototype, which describes a run but cannot re-run it).
- 2026-09-02 (RR05 Q4, the second escalation of the final-fit mechanism): `nested_final_fit()` is kept. The two tune functions D-041 names do not perform the recipe (`fit_best()` needs a saved workflow and user-built seeded resamples; `last_fit()` never fits on all rows), and a documented recipe reintroduces the procedure restatement D-041 removed. Reopen if tune ships a refit-the-recorded-procedure path reading a run's resampling specification (D-002 boundary), or if grid/Bayesian parity in print, summary and oracles becomes a recurring cost with each new orchestrator.
